# Health OS v2 — ハル UXビジョン

Date: 2026-03-04
Status: CEO承認済み

## アプリのビジョン

> スマートデバイスの包括的な健康データから、からだについて様々な視点で分析・アドバイスしてくれるパーソナルヘルスパートナー

**競合との差別化**: Oura/WHOOP/Fitbitは単一デバイス・単一ドメイン。このアプリはHealth Connect経由で全デバイスのデータを統合し、ドメイン横断の因果関係を語れる。

---

## 1. キャラクター: ハル

### プロフィール
- 1キャラクターに統合（旧3AI: ユウ先生/サキさん/マイコーチ → 廃止）
- 予防医学に詳しい健康アドバイザー、女性、30代前半
- 「あなたの健康データを毎日見ている、かかりつけのパートナー」

### 話し方のルール
- です/ます調だが堅すぎない
- 「観察」ではなく「分析」: なぜそうなっているか、だからどうなるかを語る
- ユーザーの実データを複数組み合わせて推論する
- 抽象的な励まし禁止。数値と具体的な根拠で語る
- 「だからなに？」テスト: 全ての文が「ユーザーの関心事」に接続しているか確認
- データにない事実の推測禁止（歩数が多い理由をでっちあげない等）

### カバー領域
睡眠 / 活動（歩数・カロリー・運動） / 体組成（体重・体脂肪・BMI） / バイタル（血圧・心拍） / 食事（カロリー・PFC・全栄養素・サプリ）/ ドメイン横断の因果関係

### 毎日全領域に触れる必要はない
その日「語るべきトピック」をハルが選ぶ:
- 大きく変化したもの
- 注意が必要なもの（3日連続の傾向変化など）
- ドメイン間の因果（睡眠→血圧、活動→体重など）
- ユーザーが気にしているはずのこと（暗黙の問い）

### 医療助言ガイドライン
- OK: 「あなたのデータではこう出ています」（データ分析）
- NG: 「〜の疑いがあります」「〜すべきです」（診断・処方）
- 診断しない、病名を出さない
- 「〜すべき」ではなく「〜という選択肢があります」
- 医学基準に触れる時は「一般的な基準では」と前置き
- 深刻な異常値 → 「医療機関への相談をお勧めします」で止める

## 2. AI 2層構造

### レイヤー1: 毎日の統括ブリーフィング（自動）
- 毎朝自動生成（sync時トリガー）
- 14日分のデータからパターンを分析し、最重要トピック2-3に絞る
- 暗黙の問いに答え、具体的な提案を1つ
- 400-800文字（旧: 80-150文字 x 3人 → 統合して深く）
- 出力: プレーンテキスト（JSON不要）

### レイヤー2: カスタムレポート（ユーザー起点）
- 固定テンプレートから質問を選択
- ハルが自分のデータを使って深く分析
- GPTレベルの深さ（メカニズム説明、予測、具体的アクション）
- 回数制限なし
- 保存して後から読み返せる（履歴閲覧）
- 800-1500文字

### カスタムレポートのテンプレート
- 体重・体組成（痩せたい、体脂肪を減らしたい）
- 睡眠（質を上げたい、寝つきが悪い）
- 血圧（下げたい、安定させたい）
- 運動・活動（もっと動きたい、消費を増やしたい）
- 食事・栄養（バランスを改善したい、PFC調整）
- 総合（最近の体調を分析して）

### 質問提案（Phase 2以降）
データから動的に提案:
- 「体重が3日連続で増加中。原因を分析する？」
- 「睡眠時間が先週から30分短くなっています」
- 「血圧が安定してきた理由を知りたい？」

## 3. ホーム画面: 朝のブリーフィング

### 設計思想の転換
- 旧: 「今日のダッシュボード」（スコア + 目標進捗）
- 新: 「朝のブリーフィング + 今日の状況」（物語 + 文脈付きデータ）

### 構成（上から順に）
1. **ハルのブリーフィング** — 統合分析テキスト（最重要）
2. **昨日のハイライト** — 全ドメインの実数値 + トレンド矢印（▲▼→ vs 14日平均）
3. **今日の状況** — ライブデータ（控えめに表示）
4. **ハルに聞く** — カスタムレポートへの導線（テンプレート選択）

### スコアの扱い
- スコアは「成績表」ではなく「体調のバロメーター」
- 単体の数字ではなく、トレンド（先週比、14日平均比）とセットで表示

---

## 4. データ表示の原則

### 目標なし、ベースライン基準
- 固定目標（8,000歩/7時間睡眠）→ 廃止
- 代わりに本人のベースライン（14日平均）が基準
- プログレスバー → トレンド矢印（▲▼→）
- 達成/未達成 → 「あなたの最近のパターン」

### 単日データには必ず文脈を添える
- 14日平均との比較
- 先週比
- トレンド方向
- ハルの一言解釈

### 例外: 体重目標は残してよい
ユーザーが自分で設定した意味のある目標（80kgにしたい等）。ただしプログレスバーではなく、ハルの言葉で進捗を伝える。

## 5. 日付モデル

- `daily_reports.date` = 分析対象データの日付（data date）
- ホーム画面クエリ: `WHERE date <= ? ORDER BY date DESC LIMIT 1`
- LLMプロンプト: 「ユーザーは翌朝に読む」と明示
- 「今日」禁止、「昨日」「前日」で記述、提案のみ「今日」OK

## 6. 食事機能

### 入力方式: Gemini AI解析
- テキスト or 写真 → Gemini APIで食品・栄養素を自動解析
- 全栄養素対応（下記MECE栄養素リスト）
- サプリも銘柄名で解析可能
- Geminiは「初回の種データ生成器」、確認済みデータはローカルDBに蓄積
- 検索優先: 入力 → まずローカルDB検索 → ヒットしなければGemini API

### MECE栄養素リスト（Gemini出力仕様）

**マクロ栄養素:**
- エネルギー (kcal)
- たんぱく質 (g)
- 脂質 (g) → 飽和脂肪酸 / 不飽和脂肪酸（オメガ3, オメガ6） / トランス脂肪酸
- 炭水化物 (g) → 糖質 / 食物繊維

**ビタミン（13種）:**
- 脂溶性: A, D, E, K
- 水溶性: B1, B2, B6, B12, C, ナイアシン, 葉酸, パントテン酸, ビオチン

**ミネラル（13種）:**
- 主要: Na, K, Ca, Mg, P（リン）
- 微量: Fe, Zn, Cu, Mn, Se, Cr, Mo, I（ヨウ素）

**その他:**
- コレステロール, プリン体, カフェイン, アルコール

※ 該当するものは全て返す、データがないものはnull

### 入力フロー
1. ユーザーがテキスト入力 or 写真撮影
2. Gemini APIが食品を特定、全栄養素をJSON返却
3. ユーザーが確認・修正
4. 確定 → DB保存 + お気に入り登録可能

### データ蓄積（食品DB自動構築）
- 確認済みの食品は `food_items` テーブルに蓄積
- 次回以降はローカルDB検索 → 1タップで入力（使うほど手間が減る）
- 外食チェーンの公式データも蓄積対象
- `food_items` スキーマ: id, name, brand, amount, kcal, protein_g, fat_g, carbs_g, micros_json, source("gemini"|"manual"|"official"), verified, use_count, last_used_at

### 栄養素データのLLM連携
- ブリーフィング: 日別マクロ（kcal, P, F, C）を14日テーブルで渡す
- 微量栄養素: 対象日分の詳細を添付（14日全部はトークン過多）

## 7. LLMプロンプト設計

### ブリーフィング用プロンプト構成

**System prompt:**
- ハルのキャラクター設定
- 話し方のルール
- 医療助言ガイドライン
- 分析手順（パターン発見 → 暗黙の問い → データ根拠の分析 → 提案1つ）
- 禁止事項（事実でない推測、「今日」、抽象的励まし）
- 時制ルール（「昨日」「前日」を使う、提案のみ「今日」OK）

**User prompt:**
- 対象日 + 「ユーザーは翌朝に読む」明示
- 14日分の実データテーブル（steps, sleep, weight, fat%, BP, active_kcal, total_kcal, intake_kcal, protein, fat, carbs）
- 対象日の微量栄養素詳細（食事データがある場合）

**出力:** プレーンテキスト（400-800文字）

### カスタムレポート用プロンプト構成

**System prompt:** ブリーフィングと同じ + テンプレート別の分析フォーカス指示
**User prompt:** ブリーフィングと同じデータ + 選択されたテンプレート
**出力:** プレーンテキスト（800-1500文字）

## 9. 3AI→1AI データ移行

- 既存の `ai_reports` テーブルに `briefing` カラム追加
- 旧データ（yu/saki/mai）はそのまま残す
- 表示時: `briefing` があればハル形式、なければ旧形式で出し分け
- 新規レポートはすべてハル形式（briefingのみ、yu/saki/maiは空）
